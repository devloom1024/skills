# project-docs Skill 设计

日期：2026-10-29

## 问题与目标

为当前 Skill 仓库增加 `skills/project-docs/`，让其他项目采用 DeepSeek Harness 的文档职责划分、内容要求和维护方式，并吸收 Magpie 的经验晋升机制。完成标准是另一位 agent 能独立初始化、整理、维护或审查目标项目的文档，且不会覆盖用户约束、编造实现或生成无用的目录。

## 已确认的设计

采用「规范＋模板＋检查」。组织规范规定事实归属，内容规范规定适用的信息完整度，维护规范规定变更触发、决策生命周期和 LESSONS 晋升。目录规模随真实需要增长，约束强度不随目录数量降低。

根 `AGENTS.md` 保存常驻指令与导航；局部 `AGENTS.md` 只补充局部规则；架构说明跨模块协作；子系统参考保存语义、状态与接口；模块 README 保存模块契约；Cookbook 保存可操作步骤；Agent Notes 保存长期取舍；Postmortem 保存事故证据；LESSONS 保存尚未正式化的有效教训。网站和自动生成参考在实际存在时再建立。

Skill 有初始化、迁移、维护、审查四个入口。普通功能开发仅按目标项目已有指令同步受影响文档，不触发全仓迁移。审查默认只读。已有 ADR、构建工具、文档语言和用户指令优先适配，通过明确映射实现相同职责；不强制迁移目录以满足外观。

## 内容规范

每类文档定义读者与查询问题、必要信息、条件性信息、不应出现的内容和核对证据。规范检查语义完整性，不把标题齐全当成内容正确。架构与参考描述当前事实；教程顺着前提和操作顺序组织；失败、所有权、生命周期、兼容性、限制在适用时不可省略。

每类文档提供可选模板。未知内容不猜测：缺失证据在交付报告列出，影响正确执行时再向用户询问；不能留下假装完成的占位文字。模板本身允许显式占位符，使用时必须替换或删除不适用项。

Agent Notes 沿用 `{lifecycle}/{class}/YYYY-MM-DD-topic.md`，活动状态是 proposed、implemented、rejected；archived 是已实施记录的历史归档。提案完成后改写成当前决定，不保留未完成计划。替代方案只记录真实考虑过的内容。

LESSONS 由真实返工、漏检或事故触发，每条带适用场景、规则、证据、发生日期和状态。同类问题在三个不同日期出现是晋升建议，单次高影响事件也可有理由地直接晋升。正式规则进入所属规范，LESSONS 留简述和引用，不复制完整规则或每日流水账。

## Skill 文件组织

- `SKILL.md`：精确触发条件、流程选择、基本约束、验收与资源导航。
- `references/document-ownership.md`：职责、现有结构映射、通用写作规范。
- `references/content-contracts.md`：各类文档的内容要求和审查依据。
- `references/adoption.md`：初始化与迁移步骤、持久化项目规则、兼容入口。
- `references/maintenance.md`：按变更选择更新范围和审查输出。
- `references/decision-records.md`：格式、状态、归档与替代方案要求。
- `references/lessons.md`：记录、晋升、退役规则。
- `references/examples.md`：一个完整示例项目的架构、参考、教程、决策、经验之间的分工。
- `references/sources.md`：来源、版本与通用化边界。
- `assets/templates/`：按需使用的文档起点，不批量复制。
- `scripts/check_docs.py`：Python 3.10+ 标准库、只读、JSON/文本结果、明确检查范围。
- `agents/openai.yaml`：发现元数据，保持默认自动选择。
- `tests/`：真实临时目录测试和行为评估用例、结果。

Skill 可独立分发，不依赖 `.cache`、本机绝对路径、上游运行环境或另一项 Skill。

## 自动检查边界

默认检查根入口、维护中的 Markdown 本地文件目标、决策路径/状态/章节、显式配置的字数预算和未填占位符。排除 Git、缓存、依赖、构建产物和第三方内容，归档正文不作为当前语义规范检查。归档记录仍要符合归档元数据；从活动文档进入归档的引用提示人工确认其用途。

脚本不访问网络、不执行文档命令、不改写文件、不证明源码和文档的语义一致性。Markdown 检查是有限子集：识别行内/引用式/图片的本地文件目标，忽略代码围栏、行内代码和外部 URI；锚点仅提示不在本版覆盖。无法读取、配置无效、零有效文档都不得报告为成功。符号链接目标必须留在项目内，扫描不跟随链接目录。

配置可声明已有 ADR 的目录/角色映射、额外排除项和每文件预算。中英混合以 CJK 字符和其他单词分别计数，规则有明确名称；仅对显式声明的预算执行硬限制。脚本区分机械错误和待确认提示。

## 验证

先用无 Skill 的独立 agent 在隔离目录执行真实文档请求，记录实际结果；写 Skill 后用同类场景验证。覆盖已有规则保留、空项目不虚构、已有 ADR 适配、决策完成改写、经验晋升。自动检查测试使用临时目录，覆盖坏链接、代码示例误报、引用式链接、混合语言预算、决策状态、缓存排除、无效配置、只读性和重复执行。

Skill 校验器只证明元数据和结构，最终交付同时报告脚本测试和行为评估的实际结果。当前分支直接工作，不创建 worktree。初版不引入网站投影、TypeScript API 生成、双语配对或定时复盘。
