# 评审 Skill 验证记录

日期：2026-10-29。使用三个本地Git项目的相同原始副本，执行者不读取隐藏判定、其他评估或不允许的Skill。场景包含指定提交与脏工作区不同、本地三层改动、无缺陷等价重构；无真实远端PR、凭据或生产资源。

## 预先核对的样本

同版本隔离探针确认：base执行入口拒绝guest、读取失败保留原配置、任务取消释放资源；head移除执行器鉴权、将读取错误回退为空对象、把close移到await之后，三项保证均破坏。工作区只修好了head中的权限问题，不能代替指定提交。

head的现有三项正向测试仍全部通过。clean只改变返回值临时变量，base/head通过全部控制探针。本地样本的暂存配置、未暂存执行入口和未跟踪preview各有一项实际缺陷，预览写盘由新文档只读契约和临时文件字节变化证明。

## 基线与独立使用

无Skill的独立执行者已找到committed的3项与local的3项缺陷，clean无缺陷；准确区分提交/工作区，核对head而非工作区修复。未将基线已有能力记作失败或新增收益。

仅使用code-review的另一执行者同样发现上述6项，clean没有凑问题。它记录base/head OID、index与工作区blob、未跟踪入口，使用系统临时快照运行指定版本和base对照；没有读取其他Skill。committed base/head、clean base/head、local HEAD/index的现有测试各3/3通过，local最终工作区2/3通过、UI拒绝用例失败；错误/取消/覆盖/预览探针进一步证明绿色测试未覆盖的真实回归。

未修改项目源码、测试或HEAD，暂存文件内容与阶段信息不变。主执行者完整字节比较发现两位评估者的Git查询均刷新了3个项目的index缓存元数据，因此不能宣称第一次运行index字节完全未变。初次仅强化禁可选锁仍未解决；主执行者随后对每条命令使用新副本定位到普通git diff的自动索引刷新。源文件和除index缓存外的Git文件保持原样。

补上`diff.autoRefreshIndex=false`后，在三个新的原始副本逐命令核对8类查询（status、rev-parse、cached diff、工作区diff、未跟踪、stage清单、HEAD源码、index源码），共24次查询均保持所有文件及Git元数据SHA256不变。diff同时禁用external/textconv，命令配置不改全局设置。该结果支持本环境下的具体命令，并不证明任意Git扩展或并发外部进程都无写入。

## 修正与限制

- 本地查询的只读性需保护缓存元数据，不能只看status和暂存内容；同时禁可选锁和diff自动刷新，并关闭外部输出转换。
- Windows子进程默认GBK曾导致UTF-8中文blob读取失败，改成显式解码后完成；失败读取未当作证据，补充环境说明。
- 资源类型和具体生产影响未知时应区分确定的清理缺陷与严重度推测，增加报告校准要求；执行者复核后将资源清理和预览写入从P1降为P2，保留已有实际越权和字节丢失证据支持的P1。
- 独立内容评审未发现其他具体规则冲突；它只审文档，不冒称执行了行为场景。

这些小样本不能给出任意项目的整体漏报/误报率。没有访问真实PR服务或运行push/retarget场景；相关流程只做内容评审。公开消费者、其他平台、真实系统权限错误和资源close自身失败等未验证范围分别报告，不增加未经证实缺陷。缺陷位置依据被审快照，不引用工作区修复后的位置。

## 项目规范增量验证

2026-10-30，在相同本地 Git 原始副本分别由独立执行者使用修改前后 code-review，固定 base/head 评审 app 导出器从 infrastructure 入口写盘变成直接 Path.write_text。根指令和 README 指向 conventions/index，提交版已采纳的依赖条款禁止 app 直接持久化；工作区恰有未提交的规范放宽。样本另有非强制提前返回建议、未采纳异步草案、仅约束配置更新的防错页，以及只管 docs 示例的局部 AGENTS。

旧版已正确发现条款、排除工作区放宽和无关规则，但将唯一规范违反标成 P2 缺陷，虽未证明输出故障。新版准确引用 head 条款、作用域、diff 行与例外判断，将其单列为正式规范不符合，不赋予项目未定义的运行等级；未制造其他缺陷。

两位执行者都在隔离环境调用固定 OID 的真实公开入口，base 调用 infrastructure writer 一次，head 零次；中文 JSON 均可往返，返回值一致，新版额外确认输出字节一致。探针包装 writer 仅统计并继续真实写入，没有以 mock 返回代替实现证据。主执行者对两个完整样本（含 Git 元数据）的前后 SHA256 清单比较均一致，确认评审查询和隔离验证未改源文件、文档、index、HEAD 或其他 Git 文件。

本次独立评审使用已有 conventions 路径，新默认 standards 组织由 project-docs 另一个新项目样本实际应用。无规范入口的检索回退、规则在同一提交中变化、冲突条款等只完成内容复核并列入后续验收场景，未冒称已执行；没有真实 PR、网络或全平台故障矩阵。这些有限样本不证明任意规则均可正确识别。
