# 项目规则适配与最小默认规范

## 先读实际约定

目标项目的 AGENTS、决策 README、ADR 格式与状态定义决定操作。已有 accepted 可能只表示批准；用代码、测试和项目状态语义区分批准与实施。不因为采用本 Skill 改掉编号、公开路径、分类或历史头部。

没有记录规范时才用以下默认起点，并将实际采用的约定写到目标 `.agents/notes/README.md`；后续以该项目文件为准。本 Skill 不要求 project-docs 安装或访问它的资源。

## 默认起点

路径为 `.agents/notes/{proposed|implemented|rejected}/<class>/YYYY-MM-DD-topic.md`；已实施历史归档为 `.agents/notes/archived/<class>/YYYY-MM-DD-topic.md`。类别按实际使用选 architecture、feature、bug-fix、simplification、process、testing，不预建空目录。日期是首次提案日期，移动时不变；文件名小写英文连字符。

头部为 `# Agent Note: 主题`、空行、`Status: 状态`。中文正文：提案写问题、提案、考虑过的替代方案、验收标准、风险；已实施写问题、决定、考虑过的替代方案、后果；拒绝保留提案并在状态写 `rejected — 理由`。英文等价章节可以按已有约定使用。

替代方案只写实际考虑过的选择和理由，历史缺失则明确无法还原。机械编辑、局部展示和无需长期解释的改动不强制新增记录。记录理由，当前接口与行为保证链接所属参考，不复制全量契约。

implemented 的当前事实随实际代码调整；不同决定用新记录交叉引用，不能把旧结论偷偷改成相反决定。归档只能针对完成且不再指导当前维护的决定，保留 implemented，插入 Archived 日期后冻结正文，工具格式和清单见 [归档规范](archive.md)。

## 项目规则缺失或冲突

现有约定不足以判断时，先依据范围和实际证据补充最小约定，不虚构审批角色或自动扩大权限。会改变项目既有状态含义、破坏公开引用或删除有用理由的冲突需要先明确；独立的只读审查仍可继续。

默认封存工具只实现上述 Agent Note 头部，不代表所有 ADR 都应转换。保留非兼容 ADR 的格式并使用项目现有完整性工具；没有适配工具时交付明确缺口，不声称封存完成。
