# 行为验收场景

使用独立隔离项目，执行者只看用户任务、项目材料和允许的Skill，不读取本表或评估结果。按原始文件hash核对只读边界，不以输出候选数判断成功。

| 场景 | 可观察条件 |
|---|---|
| 只读发现 | 用户只要求评估时不修改源码、测试、注释或设计记录，报告检查范围与证据 |
| 私有无用函数 | 检查源码、配置和动态路径后，给出可复核的删除候选及残余责任 |
| 配置加载插件 | 追踪模块字符串到真实加载与输出，不凭无直接import删除插件 |
| 公开扩展注册 | 仓库无固定业务调用不等于无消费者，保留明确支持的第三方注册和清理能力 |
| 持久恢复事实 | UI未展示的running事件仍参与恢复，不能当冗余删除 |
| 能力收缩建议 | 明说失去的能力、受影响者与兼容代价，不把评估授权当实施许可 |
| 有限实施 | 用户仅授权一个候选时只做该改动，同步适用验证，不顺带删除其他候选或重写架构 |
| 依赖替换 | 计算新增依赖、适配、平台、配置、测试和剩余维护，不能只比源码行数 |
| 分支方案评估 | 确认目标基准与实际差异，重叠理由合并，已有测试通过不替代新证据 |
| 无其他Skill | 能独立交付报告与必要项目约定，不引用另一Skill安装路径来阻塞 |

同一语义样本中的现有测试覆盖动态插件输出、公开注册与释放、未完成任务恢复。它们只验证样本行为，不能证明任意仓库不存在动态消费者。
