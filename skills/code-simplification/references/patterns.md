# 值得调查的简化模式

这些问题用于引导发现，不是逐项执行或强制输出候选的清单。每项判断都回到 [证据规则](evidence.md)。

## 无完整效果的能力

找没有生产者的变体、没有有效消费者的字段、每个实现均拒绝的选项、被后续配置覆盖的转发。追到实际读取和优先级，区分支持的扩展入口与没有实现的空承诺。删除连带声明、透传、拒绝专用测试和派生文档时，也要核对公开格式的兼容影响。

## 不改变消费者行动的区分

多个状态、标志或标识如果最终驱动相同行动，可检查能否在消费处简化呈现。先确认它们是否仍表达授权、驻留、持久化、恢复、所有权等不同事实。界面显示相同不等于底层事件冗余。考虑删掉概念本身，别只把同一概念挪到另一个模块。

## 用较小承诺替代通用系统

固定间隔可能替代复杂日历，明确失败可能替代自动回滚，调用方显式参数可能替代共享默认值系统。先确认实际需求，写清失去的能力与删除的整套机制；当前有消费者意味着这是行为决定，不能凭「更简单」直接实施。

## 重复权威与派生状态

查复制历史、二次缓存、失效事件后再次读取、与现有数据流并行的订阅和恢复状态。确认观察时刻和一致性要求，再评估从权威来源派生或复用。读取时脱敏不同于采集时脱敏；手动顺序不能从活动时间推导，离线缓存也可能承担必要能力。

## 错位的组合与维护所有者

查重复启动树、实际被产品使用的demo、仅负责解析依赖的模块、带独立升级周期的安装帮助器。比较已有扩展点与新分支，判断能否删除整套维护面。保留有独立责任、调用意图或完成时机的接口；少一个包不自动更好。

## 不必要的生命周期与验证层

将每个promise、flag、取消、释放、预留和回调映射到责任人与状态转换，只有表示同一事实时才合并。保留同步发布、异常传播、回滚、竞争结果裁决和释放后静止等实际保证。

检查输入来源与验证责任；外部配置、网络、持久化、队列、worker或进程传入的数据不能只因静态类型而删除运行时验证。冻结浅层对象不证明子对象不可变，同id不证明同对象。删除防御代码需说明谁仍承担真实边界保证。

## 替换自建基础设施

先看目标环境已有标准库或依赖，再考虑新依赖。计算真正删除的实现与专用测试、额外适配、传递依赖、版本/平台限制和升级责任。核对取消、截断、资源上限、假时钟、打包以及源码/构建入口；需要重建同样机制才能适配的替换没有净简化。

依赖的通用规范无需在项目重复证明，但项目特有适配与限制必须有验证。历史失败前提已变化时可以重新评估，说明新证据，不能仅以库更流行重提旧建议。
