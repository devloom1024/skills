# 方案评估、实施与验证

## 评估具体方案或分支

确认用户指定的目标基准与实际diff；不猜分支、自动切换工作区、重写历史或创建worktree。核对方案是否覆盖声称删除的全部路径，是否有重叠建议、隐藏兼容处理和新增维护。来自其他分支的理由与测试需要针对当前目标重新验证，不能直接移植结论。

对每个方案区分独立部分、重复理由、未覆盖义务和真正能力收缩。若相同决定已有所有者，更新/合并理由而非为了候选数量创建多个记录。调查本身不授权修改记录、关闭PR或发布。

## 有限实施

1. 确定用户授权的候选、实际范围与要保留的行为；已有明确授权继续执行，无需重复问许可。方案有实质新能力损失而当前任务未授权时，先报告取舍，继续独立可做部分。
2. 建立能捕获相关回归的证据。行为变化核对旧/新路径，纯删除用实际动态/公共入口检查保留能力；不要添加只断言私有符号名字不存在的脆弱测试。
3. 做最小完整改动。删除所有真正失效的透传、配置、导出、专用测试和生成来源，保留仍在验证实际能力的测试。不把无关格式化、重写或候选混进同次实施。
4. 更新所有受影响消费者、公开说明、默认值、迁移和兼容约定。生成产物从权威来源更新，不能只手改派生文件。必要长期决定按项目格式记录，局部清理无需制造提案。
5. 运行能区分方案成败的适用检查，确认实际选中范围。项目要求jmvn时使用jmvn；工具、平台和命令来自目标项目，不强制某种测试矩阵。

## 适用验证

| 影响 | 核对方向 |
|---|---|
| 动态插件/配置 | 从实际清单加载到真实消费者，不仅手工直接调用实现 |
| 公共接口/数据格式 | 受支持外部入口、输入接受、序列化、迁移与旧数据读取 |
| 生命周期/并发 | 取消、失败、中途结果、资源释放、重复调用和实际顺序保证 |
| 缓存/派生状态 | 观察时机、离线、失效、并发更新与恢复 |
| 替换依赖/基础设施 | 适配差异、上限、截断、假时钟、平台和实际部署入口 |
| 输出/性能 | 对应使用者的可观察输出或测量，不能只看局部函数更短 |

按影响选择项目已有检查；只有实际触及全仓义务、项目要求或诊断需要才扩大范围。不能通过删回归、降低断言或扩大排除让检查转绿。没有可用平台、凭据或依赖时报告未验证范围，测试通过也不能证明所有外部消费者等价。

## 失败与交付

遇到失败先复现与定位，不能继续删除来掩盖问题。报告具体版本、改动、命令、结果和保留风险；未经授权不提交、合并或推送。只读调查说明“建议”，实际实施才说明“已变更”。复用当前事实所有者，单次调查范围与临时发现进入交付报告，不写成长久项目禁令。
