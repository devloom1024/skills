# 基于证据的代码简化

寻找能减少长期维护责任的改动：实现、接口、状态、配置、依赖、测试和文档中哪些东西可以停止维护。少量有依据的候选比删除行数或候选数量更有价值。

## 模式与边界

| 用户请求 | 执行模式 | 产物 |
|---|---|---|
| 找可简化处、评估维护成本 | 只读发现 | 候选、保留/否决理由与证据缺口；不修改源码、注释、测试或记录 |
| 看一个建议或分支是否值得 | 只读评估 | 针对实际方案的收益、能力与兼容代价、替代方案和验证判断 |
| 明确要求实施某项简化 | 有限实施 | 请求范围内的改动、适用验证和受影响知识同步 |

遵守目标项目 AGENTS、架构、测试与活动决定。保护用户明确保留的能力，识别公开接口、动态加载、数据兼容、失败恢复和平台支持；不要移植其他项目的禁区。一次评估不意味着允许实施、发布、合并、提交或清理全库。后续授权覆盖到哪项就执行哪项，不反复要求已经明确的许可。

Skill 可独立使用，不要求安装其他 Skill、专用扫描器或特定语言工具。静态工具只给线索，不自动决定删除。

## 读取与判断

- 所有模式先读 [证据与候选判定](references/evidence.md)。
- 需要找方向时读 [简化模式](references/patterns.md)，需要校准时读 [正反案例](references/examples.md)。
- 评估具体方案、分支或实施时读 [验证与落地](references/implementation.md)。

1. 确认范围、模式、实际版本和用户约束；读取相关决定、代码、配置与测试，不把过时记录当当前事实。
2. 从生产者经转换、加载与消费者追到可观察效果；搜索只是起点。公共第三方接口没有仓库内固定调用不等于无用。
3. 对照既有权威来源和扩展点，判断能删掉什么、仍留下什么，以及替代实现新增的维护成本。
4. 明确分类：保留义务下的无行为变化简化；显式能力收缩；证据不足或破坏保留能力而否决/暂缓。没有高价值候选时如实报告，不凑数量。
5. 提供保留原设计的最强理由、真实替代方案、可观察验收和未验证范围。按 [报告模板](assets/templates/report.md) 的适用字段表达，不机械填空。

## 验证与知识维护

只读模式可运行范围内安全的现有检查，但不生成临时注释、提交、设计记录或自动修复。报告命令和实际结果，运行可能影响真实配置、网络、费用或生产状态时遵守当前授权。

实施模式先确定要保留的语义及回归证据，再做最小完整删除或替换。核对动态路径、错误/取消/清理、持久化与兼容等适用义务，不通过删测试、加忽略或降低断言掩盖损失。同步拥有事实的文档与生成来源，新增依赖先核对目标环境和净维护成本。

重要取舍可按项目格式记录；decision-records 可用时承担专项记录治理，project-docs 可用时指导文档组织，均非前置安装要求。普通局部清理直接报告，不强制建立新决定；默认只读发现不写记录，用户要求形成提案时才写入项目。不要把简化调查扩张成记录全库归档。

## 完成报告

说明实际检查的范围/版本、候选分类、来源与消费证据、删除和新增责任、能力与兼容影响、保留理由、验证和未知项。实施时报告具体变化和适用检查；发现时不把未实施建议说成已完成。不能把有限静态搜索或测试通过称为穷尽证明。
