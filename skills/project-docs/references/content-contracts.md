# 各类文档的内容契约

内容契约规定必须讲清楚的问题，不要求逐字照抄标题。只有实际适用的信息才展开；无证据时明确缺口，不填入看似合理的答案。先读 [事实归属](document-ownership.md)。模板目录是 [templates](../assets/templates/)。

## 项目 README

读者需要决定是否使用、如何开始和下一步读什么。必要信息是项目用途、当前可用范围、真实的最短使用路径、前提和维护入口。安装、部署、许可、截图和支持渠道在确实存在时说明。未实现项目只写已有目标与状态，不伪造快速开始。验收：新读者能区分可用能力和未来方向，入口链接有效。

## 根 AGENTS.md

读者是每次进入项目的 coding agent。必要信息是项目定位、按任务阅读入口、真实命令入口、项目特有架构约束、验证选择和文档同步触发条件。已有用户约束原意必须保留。命令说明要区分已执行和仅从配置发现；跨平台或凭据条件只在存在时写。

每条常驻要求尽量一到三行，说明条件、行动和详细依据。完整事故、领域防错清单、长教程、单次任务计划不属于根文件。验收：agent 能决定先读哪里、改哪里、怎样确认完成；不能仅写「遵循最佳实践」。

## 子目录 AGENTS.md

必要信息是适用范围、局部约束、需要额外阅读的所属参考。只有根规则不足以约束该目录时创建。不要改变根规则含义或影响兄弟目录。验收：每条新增规则都能解释为何只在该子树适用。

## docs/AGENTS.md

必要信息是文档职责表或其本地唯一来源、实际采用的目录内组织约定、当前与历史分离、教程与参考的组织要求、文档同步与证据、语言与链接方式、篇幅政策和可用检查。目录规则覆盖文件单位、命名、平铺/分组、入口、资源和稳定路径例外，详见 [目录契约](directory-layout.md)。目标项目运行时不应依赖此 Skill 的安装路径；持久化规则必须足以在新会话执行。

## 目录入口页

读者需要判断这个目录是否包含目标内容、应先读哪一页。必要信息是范围和读者、当前有效的直接子主题/子目录链接、每项解决的问题或拥有的内容、可解释的阅读顺序；相关条件或前提在影响选择时说明。入口命名和是否需要独立文件遵守 [导航规则](directory-layout.md#入口与可发现性)。

不复制子页面正文、生成 API 清单或整棵目录树，不创建占位链接，也不为决策状态目录重复维护集中清单。已有网站入口或父级导航足以承担职责时复用，不强制创建第二入口。验收：读者能选择正确的所有者，实际页面可发现，新增/迁移时对应导航同步更新。

## 用户指南

读者是产品使用者。必要信息是具体任务、真实前提、最短操作、可观察成功、适用的失败处理及后续阅读。起步页选择一条有依据的首次成功路径，进阶页围绕真实任务展开；贡献开发、内部实现细节不混进操作流程。

只有实际产品任务存在时创建，目录入口按任务和依赖组织。命令或界面操作未经实际运行时明确验证限制，不能把设计设想当可用流程。验收：用户无需先了解内部架构也能执行任务并判断结果。

## architecture.md

必要信息是系统目的与边界、主要组成和责任、关键请求或数据如何跨模块流动、依赖方向、扩展位置和重要不变量。持久化、进程分离、部署拓扑、安全边界仅在实际存在时描述。链接子系统和模块所有者，引用源码入口。

不放完整 API 或类型清单、不逐函数解释，不夹带未实施蓝图。验收：维护者能判断一项新行为应该落在哪个现有模块或扩展点，以及会影响谁。

## 子系统参考

必要信息是职责边界、实现/数据的权威来源、参与方、主要运行路径、接口的输入输出语义和约束、适用的失败行为、源码和验证入口。字段解释应覆盖类型签名无法表达的单位、默认值、缺失与空值差异等。

涉及状态时说明允许的转换、发起者与提交点；异步时说明顺序、并发、取消和清理；数据持久化或协议时说明版本、兼容和恢复；资源时说明取得、使用和释放所有者。无此机制无需杜撰章节。

验收：调用方和实现方可以据此独立实现相容行为；异常或取消后处于什么状态能查到答案。泛泛的「管理任务，支持增删改查」不合格。

## 模块 README

必要信息是用途与边界、消费者、使用入口或最小配置、输入输出语义、外部副作用、限制、源码与所属上层参考。配置存在时写类型、单位、默认值、必填条件和非法配置后果。扩展点、初始化/清理、缓存、并发、错误所有权在适用时说明。

对直接影响模型的模块，补充 Model Experience：模型看见什么、何时出现、token 增减、KV cache 前缀复用的影响及触发变化；不承诺提供商一定命中缓存。普通库无需模型相关章节。已知限制只写真实的消费者缺口和维护约束，不用想象的未来工作填满模板。

验收：消费者能正确使用并预测失败与资源后果。引用已生成 API，不复制全量 JSDoc 或其他模块的内部实现。

## development.md

必要信息是实际工具与版本约束、依赖准备、启动与日常开发路径、构建输出和检查入口。只把真实工具配置作为版本和命令依据。额外环境变量、外部服务、平台差异和故障恢复按实际说明，不能要求读取或展示凭据。验收：适合该项目的新开发者能按顺序到达可工作的开发环境；未运行步骤明确列出。

## testing.md

必要信息是实际测试层级和覆盖对象、按变更范围选择验证的规则、真实命令入口、隔离要求、测试结果的成功/失败/跳过含义。存在网络、付费 API、凭据或平台限制时标明条件。行为变化应有能捕获回归的证据，不把编译成功等同运行正确。

按项目的测试成本、影响范围和 CI 能力决定局部检查与全量检查的分工。模块专有夹具放测试所有者附近。验收：agent 能解释为何选择这些检查、漏掉了什么，证据对应实际变更版本。

## Cookbook 教程

默认面向贡献者的实现、集成或维护操作，产品用户任务默认由 user 拥有；已有项目在 Cookbook 保存产品教程时按明确角色映射保留唯一正文。必要信息是读者起点、明确目标、真实前提、按依赖顺序的操作、每个关键步骤的可观察验证、常见失败与恢复、后续参考。说明操作副作用和清理要求中适用的部分。示例必须能在所述环境使用，不把示意伪代码标为可直接运行。

验收：执行者能判断当前是否成功、失败后怎样继续。长篇理由链接决定，不中断操作路径展开论证。

## Agent Note

遵守 [决策生命周期](decision-records.md)。问题必须不预先包含解决方案；提案描述预期和验收；已实施记录描述当前决定与后果；所有记录保留真实替代方案及理由。验收：未来维护者理解选择与代价，不会把未实施计划当现状，也无需重复讨论已知替代方案。

## Defensive pattern

必要信息是适用条件、必须维持的性质、阻止的具体错误、评审判断方法、适用边界、正反例和验证入口。确有例外时说明项目规定的决策责任和例外理由，不凭模板创造审批角色。

规则须来自当前项目的实际需要或已有证据。验收：两位评审者能根据同一观察判断是否违反，不只有「注意并发」「保证安全」之类口号。

## Postmortem

必要信息是可核对的影响、事件和时间线、触发条件、直接根因与促成因素、为何此前验证未发现、修复、防复发负责人或已有责任机制、验证结果及未决项。已证实与推测分开。事故叙事只在此处展开；长期规则和当前行为引用所属文档。

验收：读者能复核因果链和修复范围，行动项有可观察的完成依据。无人执行的愿望不写成已完成防护。

## LESSONS.md

遵守 [经验生命周期](lessons.md)。每条有具体适用场景、可执行规则、真实失败证据、独立发生记录、状态与去向。验证尚未完成时明确说明。晋升后只保留摘要与链接，领域规范不堆进根指令。验收：下一次相同风险出现时知道采取什么行动，且能核对经验来源。

## 生成参考与网站

存在生成器时标明权威输入、生成命令、产物和新鲜度检查；命令和模板必须来自当前项目。网站复用文档源，只管理导航、样式和发布，不维护第二份正文。验收：能从权威来源重建产物，手工编辑限制明确；没有这些机制的项目无需创建。
