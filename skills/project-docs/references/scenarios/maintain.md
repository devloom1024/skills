# 已采用项目：随开发更新

适用于已实际完成采用后的开发同步、局部文档维护、漂移检查与规范升级。先读项目自身指令、受影响的参考与决定，再按 [AGENTS](../standards/agents.md)、[docs 总则](../standards/docs/README.md) 和 [Notes 接入](../standards/notes.md) 核对，不重复初始化。

## 修改前读取上下文

从根与适用子树的任务入口定位实现、局部要求、当前参考及相关活动决定。改动前理解已有取舍和被否决方案，不仅看最终代码。已有入口不能找到关键信息时，应修复阅读路径，而不是要求后续 agent 通读全仓。

发现未完成旧树时按 [迁移](migrate.md) 处理该范围；普通局部开发不自动扩展为全库清理。用户只要求检查时默认交付问题与证据，不实施修复。

## 判断本次影响

| 变化 | 同步所有者 |
|---|---|
| 系统组成、依赖、扩展位置与重要不变量 | architecture 与受影响参考 |
| 跨模块职责、接口、状态、失败或兼容保证 | subsystems 与实际模块消费者 |
| 模块使用、配置、默认值、资源与局限 | 模块 README；必要时子系统参考 |
| 环境、启动、构建 | development；具体操作教程 |
| 测试入口、隔离、策略或结果含义 | testing 与局部测试说明 |
| 产品操作、界面或使用前提 | user 与相关资源 |
| 实现、集成与维护步骤 | Cookbook 与样例 |
| 已采纳要求新增、变化或退役 | standards 与行动入口、规范导航 |
| 决定事实、理由或取代关系 | 调用外部 Notes Skill |
| 事故与漏检 | 适用 postmortem、当前参考及已采纳措施；不编造事故记录 |
| 路径、分组与资源变化 | 最近有效导航、全部受影响入链与消费者 |
| 纳管文档新增或路径变化、检查工具变化 | 文件预算、检查配置与本地/CI 入口 |

纯内部改动没有改变文档拥有的事实时无需制造正文变更；Notes 是否需要处理由外部判据决定。已有所有者优先更新，不因每次改动新建一份相似文档。

## 实施与验证

核对最终 diff、调用方和实际运行路径，更新唯一所有者，保留适用失败、生命周期与兼容说明。事实变化与理由改变分别处理，不能把已有决定悄悄改成相反结论。

操作教程按实际步骤核对，路径变化全仓搜索旧引用。按影响执行机械检查、源码核对、必要命令及外部 Notes 验证；代码未变化无需默认运行全应用测试，影响构建输入则验证相应消费者。用户限制验证范围时明确未验证项，不声称通过。

**日常使用项目内检查入口，不重复复制脚本。** 核对预算是否覆盖新增或移动的常驻文档；超限按总则处置，不自动提高上限。发现未接入的检查能力时按 [接入说明](../tools/check-docs.md) 补齐适用范围，报告其实际状态。

## 漂移检查

逐项报告文件位置、适用条款、证据、影响对象与建议所有者。区分已证实错误、需要实现核对的内容缺口和可选改进，不把写法偏好伪装成运行缺陷。

检查当前事实是否准确，关键条件和失败是否完整，是否重复/混入历史与提案，页面和资源能否找到，相关决定与引用是否同步。无发现也报告读取范围和未验证部分，不能把有限核对说成穷尽证明。

## 规范升级与交付

读取项目记录的基线和实际采用内容，与当前标准比较职责、布局、阅读入口、内容要求和依赖变化；对未记录基线的项目按实际符合程度判断，不假定已采用。只处理适用差异，合法例外继续保留依据，旧残留按迁移处理。

外部 Notes 升级先读实际新版本，按其规则核对项目接入与现有记录，不仅修改来源版本。应用后写回真实基线与依赖信息，未完成部分保持部分采用状态。

检查脚本升级先比较来源记录、项目定制与新版差异，保留有效修改；核对配置、运行环境和 CI 兼容后更新，不直接覆盖。

交付本次更新的所有者与原因、规则/事实/决定的同步结果、实际验证和遗留事项。不自动提交、发布或发起全库治理。
