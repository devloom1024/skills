# 旧项目：迁入统一标准

适用于已有文档尚未符合标准，或部分采用后仍有旧树的项目。目标是实际收敛，不能在旧结构上只叠加入口。先读 [AGENTS](../standards/agents.md)、[文档总则](../standards/docs/README.md) 和 [Notes 接入](../standards/notes.md)，再按材料类型读专项规范。

## 1. 盘点事实与消费者

读取实际指令、入口、现有文档、相关源码、构建配置、测试、脚本、CI 和决定。大型树按目录或主题分组逐份核对，不用少量抽样声称全树处理完成。

列出每篇材料的类型、读者、当前/提案/历史混合情况、重复或冲突、独特有效信息和引用。单独盘点非 Markdown 资源及其构建、测试、工具消费者。确定语言、历史保护和用户明确保留范围。

## 2. 建立可审阅映射

产出以下材料；可放在临时工作位置或用户指定交付位置，不把一次性迁移报告永久塞进当前参考：

- 目标树：按标准仅列实际需要的文件，说明每个文件拥有的信息及读者。
- 迁移映射：`原材料 → 信息类型 → 迁入/合并/拆分/删除/历史保留/合法例外 → 新所有者 → 消费者影响`。
- 信息清单：有效当前事实、独特理由、失败与兼容保证、必要证据及其去向。陈旧事实修正需有依据，无法确认的项明确列为缺口。
- 引用清单：包括源码注释、构建与测试输入、脚本、配置、CI、忽略规则、资源和网站映射中的旧路径。

用户只要求方案时在此交付；已授权实施则按范围继续，不另加通用审批。真正未解决且阻塞迁移的选择集中提出；授权不覆盖的操作单列，先完成可独立工作，不自行缩小任务后宣称全部完成。

## 3. 按信息处置旧材料

| 材料 | 处置 |
|---|---|
| 当前设计 | 核对实现后进入架构、子系统或模块参考；提案与历史拆出 |
| 已完成执行计划 | 当前事实和仍有价值的理由迁出，任务板、进度与实现流水账删除 |
| 进行中计划或旧设想 | 核对是否仍有效；只有符合外部条件的决定进入 Notes，任务清单不机械转为 Note；过时内容清除 |
| 长期理由与被否方案 | 交由外部 Notes Skill，保留真实依据、独特后果和验证缺口，不编造历史争论 |
| 评审、审计和验收报告 | 当前问题进入所属限制或问题跟踪；可复用方法进入 testing/Cookbook；已失效结论快照清除 |
| 操作指南 | 按读者和任务进入 development、testing、Cookbook 或 user |
| 事故材料 | 有可核对事件时进入 postmortem；正式规则和当前事实各归其主 |
| 发布记录、许可与协议历史 | 保留其真实时间和发布含义，不把历史路径改写成当时不存在的新路径 |
| 图片、脚本、数据与样例 | 随信息所有者迁移；真实构建或测试输入与消费者共同处理 |

必要原文历史按项目明确保留要求安置到有职责和维护方式的位置；当前事实与理由仍要迁出。Notes 历史使用外部生命周期，普通旧文不套用 Note 冻结协议。

## 4. 分组执行完整迁移

先建立新所有者并迁入有效信息，解决当前事实与旧设想冲突，再修复全部受影响引用和消费者，最后删除失去职责的旧文件及空目录。

不能整树删除后写短摘要；不能搬旧文加「以代码为准」替代核对；不能仅因旧路径有内部引用而留兼容页。原页只有仍承担真实独立职责或有合法稳定入口约束时可保留，其范围、依据和维护方式写清；已迁出的正文不得重复维护。

可迁移的构建输入应连同消费者与验证处理，不默认永远保留旧目录。无法在授权范围完成的消费者迁移作为具体未完成项，不自创永久禁止修改源码的规则。

按 [检查器接入](../tools/check-docs.md) 复用已有检查或接入项目内脚本，为最终常驻文档配置合理预算，并更新本地与已有 CI 入口。旧路径预算、触发条件和排除项同次修正；**不能靠排除正文或按现有篇幅抬高预算宣告迁移通过**。脚本、配置和入口纳入版本管理，不依赖执行者的全局 Skill。

## 5. 对账与写回

逐项核对：原清单每份材料均有实际结果，每项有效信息在新所有者可找到，删除依据成立；全仓旧路径残留均有合法原因，受影响的构建、脚本、资源和导航按范围验证。Notes 变更使用外部检查，历史陈述和文档语言保持正确。

将实际布局、命名、入口、资源、同步与验证方式、Notes 来源、采用基线和合法例外写回项目。遗留迁移、重要信息缺口、预算与检查入口或必要依赖尚未解决时标为部分采用，不因项目声明了规范就转为全量维护状态。

交付目标与实际差异、完成的组、剩余组、信息及引用对账结果、实际命令和未验证项。用户明确只看草稿时交付草稿，不以执行评估替代用户审阅。
