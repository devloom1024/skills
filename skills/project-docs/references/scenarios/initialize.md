# 空项目：建立最小工程上下文

适用于没有成体系文档或尚无实现的项目。执行前读取 [AGENTS](../standards/agents.md)、[文档总则](../standards/docs/README.md) 和 [Notes 接入](../standards/notes.md)，按实际内容补读专项规范。

## 盘点

确认已有介绍、用户目标、指令、源码、工具配置和已作出的决定。区分已确定、已实现和未确定；配置中出现命令不等于已运行。保留现有工具、语言和 Git 等用户要求，不用模板替换。

## 建立入口与所有者

1. 以 [根指令模板](../../assets/templates/root-agents.md) 为辅助，将已确认的全仓工程规则写入根 AGENTS，局部规则写入适用子树；按需补充项目定位、必读入口和常用命令。不凭模板虚构约束。
2. 以 [文档规则模板](../../assets/templates/docs-agents.md) 为辅助，写入项目内文档标准。最小项目可用短段落，保留信息归属、只写可确认现状和按需增长的核心要求。
3. 项目 README 提供已有目标、当前状态与入口。尚无实现不编造安装或首次成功路径；已有实现则按真实源码建立必要架构、开发、测试或模块参考。
4. 只有独立读者或语义需要时才增加子系统、教程、用户文档、正式规范。无内容不创建空目录和全套骨架。
5. 按 Notes 接入规范定位外部 Skill；缺失时询问项目或全局安装，用户选择后通过 `npx skills` 自动安装并读取。记录可用性、来源和调用方式；有符合条件的真实决定才执行外部记录流程。依赖未就绪时明确部分采用，不自建替代协议。
6. 按 [检查器接入](../tools/check-docs.md) 复用已有工具或接入项目内脚本，为现有常驻文档配置预算，建立本地入口并接入已有 CI。脚本、配置和入口纳入版本管理；空项目没有 CI 时提供本地命令，不创建空的 CI 骨架。

已存在有效指令时在其基础上补充，保留用户要求与实际工具链。模板是编写提示，填写事实并移除不适用段落，不把占位符作为完成产物。

## 接通与验证

检查根行动入口能到达现有规则、参考和决定；多个读者的起步路径清楚，正文各有唯一所有者。核对纳管文件预算、检查入口及来源记录；按授权执行链接、内容与命令核对，未运行的步骤明确说明。

将采用基线、实际规则和 Notes 依赖状态写回项目。交付说明当前有哪些真实信息、尚无实现而未创建什么，以及下一次变化应更新哪里。完成的是适合当前规模的体系，不以文件数量衡量。
