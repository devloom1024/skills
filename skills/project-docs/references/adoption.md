# 初始化与已有项目迁移

## 先盘点

确认目标根目录和用户请求；读取实际生效的指令、README、现有文档、源码入口、构建配置、测试和已有 ADR。先列真实事实与未知项。发现配置中的命令不等于已经执行；运行示例时确认副作用和当前授权。

建立「现有路径 → 文档角色 → 保留/更新/迁移 → 引用影响」映射，并按 [目录契约](directory-layout.md) 确定文件单位、命名、分类与平铺/分组、入口和资源。小项目可以一份参考覆盖多个相关契约；已有有效 ADR 目录和编号、稳定网站入口保留。重复内容迁移前确认细节、例外和历史依据没有丢失。不要把没有源码的设计当成已实现架构。

## 新项目

1. 已实现内容为空时，保留真实项目介绍，建立根 `AGENTS.md` 和 `docs/AGENTS.md`。LESSONS 仅说明真实事件的记录规则，或等首个事件再建。
2. 已有实现时，按 [内容契约](content-contracts.md) 建立当前需要的架构、参考和操作说明。没有独立问题就不拆文件。
3. 从真实构建/测试配置提取命令；没有命令就如实写「尚未配置」，不要提供推测的 `npm test`、`mvn test` 等命令。
4. 依据实际使用场景增加局部指令。保留用户明确要求的 `jmvn`、语言和 Git 操作约束等原意。
5. 已有真实采纳的开发要求时，按主题放入 `docs/standards/`，防错主题默认归其 `defensive-patterns/`；先明确强制/建议、范围和验证。规范入口按任务导航，根指令链接实际入口；没有规则时不创建 standards 空树。

未实现项目的最小文档标准可以只有三段：事实各有一个维护位置；只描述可确认的现状、不编造命令或历史；出现真实实现与文档变更后再按需要增加所有者并验证链接。完整角色表在项目确实需要分类时再展开，不让规则远大于已有内容。

## 已有项目

1. 确定唯一事实所有者，优先在已有文件上修正。只有职责混杂影响使用或必须拆分时迁移。
2. 迁移内容、资源、修复入站链接和更新最近有效导航在同一次变更完成；必要时保留短期重定向入口，不能保留两份正文继续维护。网站路由或别名受影响时核对发布映射，不以 Markdown 链接通过替代公开入口验证。
3. 当前说明与提案分开。缺少充分问题、替代方案或验收的随手未来设想可保留在现有待评估区，不伪装成完整 Agent Note。
4. 显式映射已有 ADR 的位置、状态词与职责。格式不同可以保留，检查器用 `external` 映射并要求人工验证；绝不能把提示通过说成状态已检查。
5. 用 [维护流程](maintenance.md) 核对所有权和验证范围。再次执行应复用已建立文档，不重新批量生成。

## 写回长期规则

根 `AGENTS.md` 中保留项目本身的长期约束，然后增加按任务的阅读入口、验证选择、契约变化同步要求、决策/经验创建条件。领域规则完整正文写入所属规范，根指令只有条件和导航。

开发与评审的阅读入口要指向实际工程规范及相关领域规则。已有 conventions、standards 或独立 defensive-patterns 等目录时记录角色映射，保留有效路径和引用，不创建第二份正文。`docs/AGENTS.md` 的局部文档规则不自动成为源码约束，源码评审需要的规范通过根或适用子树入口明确发现。

`docs/AGENTS.md` 必须持久化事实归属、实际采用的目录内组织、教程/参考、当前/历史、内容证据、语言、篇幅和检查约定。目录内组织明确到文件单位、命名、分组、入口与排序、资源位置和稳定路径例外；小项目简述即可，不复制全套规则。可以引用目标项目内的细分规范，但不能只写「使用 project-docs」并依赖 Skill 是否安装。目标项目使用者无需访问 Skill 的本机路径或额外仓库。

项目有独立检查脚本时复用它。Skill 自带检查器可作为外部审查工具使用；只有用户请求持续工具集成时才把脚本复制进项目并接入 CI，记录调用方式和维护归属，不默认新增依赖或 CI。

采用决策记录时建立项目自己的格式/生命周期约定，写明创建前查重、部分取代、实施范围和归档冻结要求；可用 [决策约定模板](../assets/templates/notes-readme.md)。已有 ADR 则写明确映射，保留原文与编号。记录真实可用的结构检查与冻结工具、基准来源和未覆盖项；未集成时不能捏造项目内命令。专项治理可使用 decision-records，但规范本身不依赖它存在。

持久化的是跨会话仍有效的规则。不要把「本次不归档某记录」「本次只检查哪些文件」等单次授权范围写成长期禁止；这些写入交付报告。工具是否已集成可作为当前事实描述，环境快照和执行记录仍与正式规范分开，避免后续任务被旧会话范围误导。

## 多 agent 入口

存在 Claude Code 时，先读已有 `CLAUDE.md`，保留额外有效指令，公共规则由 `AGENTS.md` 维护。支持引用的环境可用 `@AGENTS.md`；已采用符号链接时保留并确认 Git 与实际环境能正确读取。不要将链接失效时的纯路径文本当作已加载规则。没有相关工具使用需求就无需创建兼容入口。

## 迁移验收

- 用户约束含义保留；工具与语言未被模板替换。
- 当前事实来自代码、配置或可核对记录；未来内容明确隔离。
- 旧内容中的有效例外、限制和理由保留，引用已修复。
- 只创建当前有用文档，输出不存在空壳或未填占位符。
- 目录中的文件单位、命名、分类和入口有明确依据，页面可从阅读入口或已声明检索方式找到，迁移后的资源引用可用；决策清单例外不被索引要求覆盖。
- 新会话能通过项目自己的指令找到规则；检查报告明确范围与缺口。
