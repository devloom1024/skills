# 初始化与已有项目迁移

## 先盘点

确认目标根目录和用户请求；读取实际生效的指令、README、现有文档、源码入口、构建配置、测试和已有 ADR。先列真实事实与未知项。发现配置中的命令不等于已经执行；运行示例时确认副作用和当前授权。

建立「现有路径 → 文档角色 → 保留/更新/迁移 → 引用影响」映射。小项目可以一份参考覆盖多个相关契约；已有有效 ADR 目录和编号保留。重复内容迁移前确认细节、例外和历史依据没有丢失。不要把没有源码的设计当成已实现架构。

## 新项目

1. 已实现内容为空时，保留真实项目介绍，建立根 `AGENTS.md` 和 `docs/AGENTS.md`。LESSONS 仅说明真实事件的记录规则，或等首个事件再建。
2. 已有实现时，按 [内容契约](content-contracts.md) 建立当前需要的架构、参考和操作说明。没有独立问题就不拆文件。
3. 从真实构建/测试配置提取命令；没有命令就如实写「尚未配置」，不要提供推测的 `npm test`、`mvn test` 等命令。
4. 依据实际使用场景增加局部指令。保留用户明确要求的 `jmvn`、语言和 Git 操作约束等原意。

未实现项目的最小文档标准可以只有三段：事实各有一个维护位置；只描述可确认的现状、不编造命令或历史；出现真实实现与文档变更后再按需要增加所有者并验证链接。完整角色表在项目确实需要分类时再展开，不让规则远大于已有内容。

## 已有项目

1. 确定唯一事实所有者，优先在已有文件上修正。只有职责混杂影响使用或必须拆分时迁移。
2. 迁移内容和修复入站链接在同一次变更完成；必要时保留短期重定向入口，不能保留两份正文继续维护。
3. 当前说明与提案分开。缺少充分问题、替代方案或验收的随手未来设想可保留在现有待评估区，不伪装成完整 Agent Note。
4. 显式映射已有 ADR 的位置、状态词与职责。格式不同可以保留，检查器用 `external` 映射并要求人工验证；绝不能把提示通过说成状态已检查。
5. 用 [维护流程](maintenance.md) 核对所有权和验证范围。再次执行应复用已建立文档，不重新批量生成。

## 写回长期规则

根 `AGENTS.md` 中保留项目本身的长期约束，然后增加按任务的阅读入口、验证选择、契约变化同步要求、决策/经验创建条件。领域规则完整正文写入所属规范，根指令只有条件和导航。

`docs/AGENTS.md` 必须持久化事实归属、教程/参考、当前/历史、内容证据、语言、篇幅和检查约定。可以引用目标项目内的细分规范，但不能只写「使用 project-docs」并依赖 Skill 是否安装。目标项目使用者无需访问 Skill 的本机路径或额外仓库。

项目有独立检查脚本时复用它。Skill 自带检查器可作为外部审查工具使用；只有用户请求持续工具集成时才把脚本复制进项目并接入 CI，记录调用方式和维护归属，不默认新增依赖或 CI。

## 多 agent 入口

存在 Claude Code 时，先读已有 `CLAUDE.md`，保留额外有效指令，公共规则由 `AGENTS.md` 维护。支持引用的环境可用 `@AGENTS.md`；已采用符号链接时保留并确认 Git 与实际环境能正确读取。不要将链接失效时的纯路径文本当作已加载规则。没有相关工具使用需求就无需创建兼容入口。

## 迁移验收

- 用户约束含义保留；工具与语言未被模板替换。
- 当前事实来自代码、配置或可核对记录；未来内容明确隔离。
- 旧内容中的有效例外、限制和理由保留，引用已修复。
- 只创建当前有用文档，输出不存在空壳或未填占位符。
- 新会话能通过项目自己的指令找到规则；检查报告明确范围与缺口。
