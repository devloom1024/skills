# 决策记录生命周期

## 规则所有者与操作边界

此处定义文档内容与基本维护要求；将实际采用的规则写到目标项目决策 README/ADR 约定，后续以项目规范为准。已有状态、编号和格式优先适配，不把 accepted 当作实现已验证。批量取代分析、合并清理和冻结操作可由独立 decision-records Skill 执行，但本 Skill 的初始化和单条基本维护无需它安装。

## 创建条件

只有代码、测试、现有参考不足以解释的长期决定理由才新增记录。实质提案进 proposed，已作出并实施的决定可直接进 implemented。机械编辑和局部调整免写；已有记录拥有同一决定时更新它。不同决定用新记录交叉引用，不把旧决定改写成相反结论。

创建前搜索同主题、机制和实际替代方案，读现有记录与引用。新决定明确是补充、部分取代或完全取代；部分取代仍有指导价值的失败保证、兼容处理或理由必须保留，不因新方案存在就归档整篇旧决定。

## 默认路径与格式

```text
.agents/notes/{proposed|implemented|rejected}/{class}/YYYY-MM-DD-topic.md
.agents/notes/archived/{class}/YYYY-MM-DD-topic.md
```

class 是 `feature`、`bug-fix`、`simplification`、`architecture`、`process`、`testing`。architecture 是产品结构，process 是围绕产品的工作方式。日期为首次提案日期，不随移动改名。文件名用小写英文和连字符，避免跨平台路径问题。

头三行固定：

```markdown
# Agent Note: 具体主题

Status: proposed
```

支持中文或英文的规范章节。提案有问题、提案、考虑过的替代方案、验收标准、风险；已实施有问题、决定、考虑过的替代方案、后果；拒绝保留原提案，状态为 `rejected — 具体理由`。正文中每个必要章节应有实质内容。

替代方案只能记录实际考虑过的选择和为何未采用。历史记录无法还原时明确说明缺失证据，不虚构争论。实质新决策在讨论时就记录真实选择，而不是为了模板补造。

## 实施完成

核对实现和测试；区分核心能力完成与所有调用方集成完成。路径移至 implemented，Status 改为 implemented；提案改写成现在时的决定，验收与风险合并为当前后果或现有验证。移除计划、迁移计划、验收标准等提案期章节，保留仍存在的缺口。

同时修复活动引用。源码结构或名字变化时更新当前 owning note 的事实；理由与取舍的历史含义不随改名重写。当前 API 契约继续由所属参考维护，Note 链接它。

## 拒绝、归档和取代

proposed 被放弃时进 rejected 并写理由，不能进 archive。仅当拒绝理由仍能阻止有诱惑力的错误选择时保留。

implemented 已不指导当前维护、但有历史价值时才归档。保留 `Status: implemented`，新增 `Archived: YYYY-MM-DD`。归档正文冻结，不能为了修路径、写法或翻译去改历史。活动文档进入归档的引用仅用于明确的历史说明；不得当作现行规则。

冻结需要项目自己的可验证机制。默认完整性清单位于 archived/manifest.json，记录顺序追加的路径、归档日期和全文 SHA256；对照已提交 Git 版本或独立可信快照保护旧条目，不能只用当前清单与当前正文互相证明。已有工具优先复用，目标项目尚无工具时明确未提供冻结验证，不能把结构检查通过当成冻结完成。恢复旧决定时新建活动记录引用历史，不解封原件。

原始字节冻结还需遵守项目Git换行和过滤器策略，避免跨平台检出改变归档字节；在项目内约定适用的.gitattributes，不改全局配置，不用重算旧哈希修饰异常。

新决定取代旧决定时交叉引用，说明谁拥有当前结论。合并删除旧记录前保留独特理由、替代方案、后果和验证缺口，修复全部入站引用。不能以 Git 中找得到为由丢掉仍需使用的理由。

## 已有 ADR

尊重原路径、编号、状态和章节，记录它们与上述生命周期的映射，不批量重写。检查器 `external` 只保留链接检查并提示人工核验，不能自动证明既有格式的状态语义。

没有 decision-records 时，先完成同主题查重、按证据维护单条记录和引用，并写出项目长期约定。需要批量清理或冻结时遵守项目实际工具和授权；缺少格式适配或历史基准应报告明确缺口，不把执行不了的部分写成「请安装另一个 Skill」代替结果。
