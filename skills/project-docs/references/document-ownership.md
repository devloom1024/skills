# 文档组织与事实归属

## 核心规则

每项事实有一个当前所有者。上层介绍自己和直接子层的职责；读者需要细节时链接到下层所有者。类型和命令已有源码权威时，解释使用语义并引用来源，不手工复制完整目录。

先确认文档读者和所需决定，再确定放置位置与详细程度。教程按依赖顺序走向一个结果；参考按查询主题说明当前行为；大量教程和参考混在一起时拆分。文档是否需要更新由契约变化决定，内部重构无需制造说明变更。

## 层级

| 角色与默认位置 | 拥有什么 | 需要详细内容时去哪里 |
|---|---|---|
| `README.md` | 项目用途、适用读者、快速开始与导航 | 操作进 Cookbook，开发进 development |
| 根 `AGENTS.md` | 每次会话需要的约束、必读入口、命令入口、完成要求 | 局部规则、设计、取舍不在这里展开 |
| 子树 `AGENTS.md` | 指定目录的附加约束 | 不重复根规则或扩张到其他目录 |
| `docs/AGENTS.md` | 文档分类、事实归属、语言和验证规则 | 各类文档的实际内容由所属文件维护 |
| `docs/architecture.md` | 系统组成、协作路径、扩展位置和重要不变量 | 类型语义进子系统，模块细节进模块 README |
| `docs/subsystems/` | 跨模块职责、接口语义、状态、失败和兼容保证 | 不复制架构全景或逐函数实现 |
| 模块旁 `README.md` | 模块使用、配置、生命周期、扩展、局限 | 不叙述其他模块内部实现 |
| `docs/development.md` | 环境和开发路径、命令用途 | 命令细目引用真实构建配置 |
| `docs/testing.md` | 按改动选择验证，隔离和结果判断 | 特定用例与夹具说明靠近测试代码 |
| `docs/cookbook/` | 一个任务从前提到验证与失败恢复 | 设计原因链接 Agent Note |
| `.agents/notes/` | 活动提案或长期决定的理由、真实替代方案和后果 | 已实施当前契约仍以所属参考为主 |
| `docs/defensive-patterns/` | 经项目采纳的正式防错要求，按领域分 | 事故叙事进入 postmortem，候选经验进 LESSONS |
| `docs/postmortem/` | 事故时间线、影响、根因和防复发证据 | 不作为当前接口参考 |
| `LESSONS.md` | 尚未正式化的经验、重复证据、晋升索引 | 正式规则完整正文只有一个所有者 |
| 仓库 Skills | 可复用操作流程和判断方法 | 产品契约留在 docs 或源码旁 |
| 生成参考、网站 | 从源码生成的查询内容，或现有文档的发布视图 | 先更新权威来源，不手改派生结果 |

需要索引时，目录 README 解释直接子文档的职责。Agent Notes 的状态和类别已经编码在目录，按路径浏览和搜索，不再维护容易冲突的集中清单。

## 规模与现有目录适配

- 尚未实现的项目：根指令、文档标准和已有介绍足够。记录技术栈未定即可，不创建架构、测试命令或空决策记录。LESSONS 可只有简短的真实记录规则，等待首次事件。
- 小项目：一个架构参考可覆盖全部协作；只有独立维护的模块或跨模块契约需要拆文档。
- 大项目：领域内规则和细节向下放；按需增加子系统、模块、测试、用户文档。
- 已有 ADR、`doc/` 或团队约定：保留稳定路径和编号，用表格说明「现有位置 → 本规范角色 → 维护要求」。显式格式映射优先，不能重写所有记录来满足模板。
- 拥有多语言、文档网站或 API 生成器时复用现有机制，不因为采用此 Skill 就额外启用。

## 共用内容质量

1. 当前参考描述可确认的现状。提案和未来计划不得冒充已实施行为。
2. 说明适用条件和使用后果，默认值、例外和未知结果不可被简化成绝对保证。
3. 涉及共享数据、异步、资源或持久化时，说明所有者、提交点、取消/释放、失败和恢复中适用的语义。
4. 命令、路径、字段和默认值核对实际代码与配置；操作说明尽可能原样执行，缺权限或外部条件时列为未验证。
5. 用具体术语描述行为，保留必要上下文；删掉推理过程、逐行代码复述、实现流水账和无关评审历史。
6. 一个自然段保持一条物理行，编辑器软换行；代码、列表和表格按结构排版。已有格式化工具冲突时遵循项目明确约定。
7. 常驻文档有项目自己的篇幅预算。超限先迁移错位内容、再压缩；确需更多空间时说明理由后调整，不能删掉必要的失败和兼容保证。

预算用于减少无关常驻上下文，不意味着把所有参考都压成短摘要。维护文档的目标是准确与可查找，文件数量不是成果指标。
