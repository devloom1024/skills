# Cookbook 编写与验证流程

## 选择任务与所有者

先确定真实读者、起点和可观察目标。默认贡献者的实现、集成、维护操作进入 Cookbook，产品用户任务进入 user；已有路径映射保留并明确。一个任务已有教程时更新所有者，不生成同义文档。目录和资源按 [目录契约](directory-layout.md)，内容按 [教程契约](content-contracts.md#cookbook-教程)。

若已有领域 Skill 实现同一流程，先判断谁维护哪种事实：目标项目教程拥有本项目入口、配置和验证要求，领域 Skill 拥有可复用操作方法。可用时引用其作用，不让项目教程依赖某个未安装 Skill 的绝对路径，也不同时维护两套容易分叉的完整步骤。

## 从真实实现提炼

1. 读当前代码、配置、示例、测试和已有教程，定位实际执行路径；不根据名称或惯例猜测命令。
2. 明确工具版本来源、工作目录、必要权限、输入、外部依赖、副作用和清理。没有实际需求的条件不填入模板。
3. 依操作依赖排序，先给最短成功路径，再给会影响选择的进阶条件。每步说明行动与可观察结果，长篇理由链接所属决定。
4. 覆盖常见失败、错误识别、停止条件、恢复和清理；不能让读者在未知状态下继续执行依赖步骤。

新流程尚未实现时保留为提案或明确示意，不发布成已可运行教程。没有源码只能依记录描述，不能宣称核对了实现。

## 执行验证

在当前授权范围和隔离环境中原样运行文档步骤，核对成功输出和实际副作用；失败/恢复说明用受控输入核对。不要为了文档验证访问用户真实配置、展示凭据或触发未授权发布。需要服务、费用、凭据或平台而无法运行时，保留真实前提并明确未执行步骤和验证责任，不改写为通过。

操作的目标必须被验证：创建文件就检查文件内容；保存配置就核对读取方实际使用；命令返回零不足以证明最终效果。命令、伪代码和示意片段分别标明。验证记录进入交付证据或项目规定位置，不把每天运行流水账追加进教程。

## 变更同步与验收

接口、配置、入口、默认值、权限、输出或恢复路径改变时，同次核对相关教程、样例、图片和链接。先修改唯一事实所有者，再更新导航和引用；不顺便把所有现有教程迁移目录。

交付时回答：读者能否按起点执行、何处判断成功、失败如何停止与恢复、哪些步骤已实际验证、哪些依赖仍缺。再次维护复用同一教程，不为了一个参数变化复制新版本正文。
