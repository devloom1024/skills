# 文档检查器

## 接入项目

**优先复用项目已有等效检查，不建立竞争入口。** 对照链接、必要文件和预算等覆盖项，补齐实际缺口；没有合适工具时，将本 Skill 的 `scripts/check_docs.py` 复制为目标项目的 `scripts/check-docs.py`。项目有既定工具目录时沿用，但不要覆盖同名文件。

默认交付位置：

```text
scripts/check-docs.py       # 项目内独立运行的检查脚本
docs/doc-rules.json         # 检查范围与逐文件预算
<现有本地检查入口>          # 使用项目内脚本和配置
<现有 CI 配置>             # 有 CI 时调用同一入口
```

脚本需要 Python 3.10+，仅标准库，只读、不联网、不执行正文命令。从目标项目根目录运行：

```text
python3 scripts/check-docs.py . --config docs/doc-rules.json --json
```

**脚本、配置和执行入口纳入项目版本管理，运行不依赖全局 Skill 或作者本机路径。** 保留脚本原始许可及来源信息；在项目既有工具维护说明中记录来源仓库、实际修订或 Skill 版本及源脚本 SHA-256，没有现成说明时用脚本头部注释记录。不添加配置格式不支持的元数据字段。用户要求提交时再执行 Git 提交。

将命令接入现有本地检查入口，或在 `docs/AGENTS.md` 写明独立命令。已有 CI 时复用现有任务并准备 Python 运行环境；让文档、指令、脚本和配置变动触发检查，链接目标删除也须能触发。失败必须使任务失败，不使用忽略错误或仅打印结果的接法。没有 CI 时不另造平台配置；提交前钩子只作辅助。

按授权验证入口可运行，并核对超限或坏链接确实导致失败；失败样例在临时副本中构造。不能运行时明确接入状态与未验证范围，用户只要求草稿或不评估时不执行这一步。

## 配置与预算

采用时显式创建配置；省略配置仅用于临时检查，此时默认要求根 `AGENTS.md` 与 `docs/AGENTS.md`，但没有预算。配置路径相对项目根定位，支持以下键：

```json
{
  "required_files": ["AGENTS.md", "docs/AGENTS.md"],
  "exclude": [".agents/skills/**", "fixtures/**"],
  "budgets": {"AGENTS.md": {"metric": "mixed", "max": 1800}}
}
```

数字仅示例，由项目实际信息需要确定。`required_files` 替代默认入口；`exclude` 是项目相对路径或 fnmatch 模式；`budgets` 按 Markdown 文件设置正整数上限，`words` 按空白词、`mixed` 按 CJK 字符及其他词计量。必需或预算文件被排除、预算文件丢失、配置未知键均报错。

**预算规则见 [文档总则](../standards/docs/README.md#篇幅与自动检查)。** 配置须列出实际纳管的根与子树 AGENTS、架构等常驻文档；本脚本按确切文件路径配置，不支持预算通配符。新增、移动或删除纳管文件时同次更新路径。计量覆盖原始全文，含代码和标记；中文或混合正文使用 `mixed`，不要把计量结果称为模型 token 数。

## 检查边界

脚本检查本地 Markdown 文件链接、图片目标、引用式链接、未填模板、必要文件和显式预算；不解析完整 CommonMark/MDX，不验证锚点、外链、路由、图片视觉、目录分类、完整可发现性或内容语义。默认跳过 `.agents/notes/`，其结构、格式、链接及冻结由外部工具负责；其他既有决策位置应按实际范围显式排除。原配置的 `note_roots` 已移除，先明确其外部验证与排除再更新配置，不能静默接受旧协议。

另默认排除各层 `.git`、`.cache`、`node_modules`、`vendor`、`.venv`、`venv`、`__pycache__`、`dist`、`build`、`target`、`coverage`、`.generated`。不遍历符号链接/junction 目录，不读取解析到项目外的文件；显式入口未扫描会报错。排除范围和报告中的覆盖范围均须披露，真实受影响正文不能靠排除隐藏。

退出码 0 为覆盖项无错误，1 为文档错误，2 为配置或读取失败。JSON 报告含 `scope`、`findings`、`summary`，不把未扫描、未运行或未检查的项当通过。

目录归属、内容语义和运行效果按 [文档总则](../standards/docs/README.md#同步与核对) 单独核对。

## 后续更新

日常维护使用项目内入口，不因调用 Skill 就重新复制脚本。升级时比较记录的来源、当前项目修改和新版差异，保留有效定制；核对配置与退出码兼容，按授权验证后更新来源记录，不直接覆盖。
