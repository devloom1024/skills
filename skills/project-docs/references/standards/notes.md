# Agent Notes 的职责与外部接入

## 职责

Notes 保留代码和当前参考难以表达的决定理由、真实替代方案与代价，让后续维护者避免重新尝试已被否决的路线。当前 API、状态和使用步骤仍由 [docs 与模块参考](docs/README.md) 拥有，待办与聊天过程不自动成为决定。

## 唯一协议来源

采用 [write-notes-like-deepseek](https://github.com/czm15053/write-notes-like-deepseek/tree/main/skills/write-notes-like-deepseek)，先读实际可用版本的 `SKILL.md`，再读本次操作相关参考。

**Notes 协议由外部 Skill 唯一定义。** 创建条件、分类、命名、语言、格式、状态流转、拒绝、取代、合并、归档和冻结验证均遵循该来源；本文件不复制这些协议，不提供另一套 Note 模板或脚本。

用户直接要求和实际生效的项目指令优先。除此以外，采用中发现本 Skill 或本地旧 Note 约定与外部协议竞争时，以外部 Skill 为准，迁移相关定义及消费者，不以「已有规则」自动保留双协议。外部 Skill 对既有 ADR 的适配也按其实际版本处理，不自行批量重编号或强制转换。

本体系不默认引入看板与额外审批。用户已决定的取舍及已有授权不重新请求确认；用户明确限制的操作不因外部流程而执行。

## 接入步骤

1. 检查当前环境的 Skill 列表、项目与全局安装目录和已有配置，定位当前 agent 可读取的外部 `SKILL.md`。已可用则复用，不重复安装或擅自升级；只有登记但文件缺失、链接失效或当前 agent 无法读取时，不算可用。网络页面可用不等于已安装。
2. 缺失时由 project-docs 主动询问：「缺少 write-notes-like-deepseek，要安装到当前项目，还是全局？也可以暂不安装。」说明项目安装作用于当前仓库，全局安装供当前用户跨项目使用。用户选择安装范围后，按下节命令自动安装，不把命令交给用户自行执行，也不为同一次安装再加确认。此前已明确选择且仍适用的范围直接沿用；未回复不默认选择。
3. 安装成功后重新定位当前 agent 可读取的 `SKILL.md` 并读取相关参考。确认本次需要的运行环境、工具、工作目录、现有 Notes 路径与验证方式。安装不等于已配置项目命令或 CI。
4. 记录来源、实际版本或可核对修订、安装范围、安装方式及可用入口。没有版本标识时如实记录来源与读取日期，不编造固定版本或已安装状态。
5. 在根/适用子树指令写入调用时机与检索入口。在项目决策约定或其现有所有者记录接入信息及真实命令；不复制整套外部协议，不引用作者本机绝对路径。在用户授权范围完成必要命令接入，不能声称依赖缺失时也已完成 Note 治理。

### 自动安装命令

在目标项目根目录执行；将 `<agent-id>` 替换为当前运行环境在 skills CLI 中的实际标识，例如 Codex 为 `codex`。只安装指定 Skill，并限定为当前 agent；不要用 `--all` 扩大范围。命令参数依据 [skills CLI 安装参考](https://github.com/vercel-labs/skills/blob/main/docs/commands.md#skills-add)。

项目安装（默认范围）：

```sh
npx --yes skills add czm15053/write-notes-like-deepseek --skill write-notes-like-deepseek --agent <agent-id> --yes
```

全局安装：

```sh
npx --yes skills add czm15053/write-notes-like-deepseek --skill write-notes-like-deepseek --agent <agent-id> --global --yes
```

两处 `--yes` 分别用于 npx 获取 CLI 和跳过安装器的重复交互，只在用户已选择范围后使用。探测 Node.js、npx 及当前 CLI 所需环境；缺失时说明实际阻塞，不擅自安装系统工具链。遇到网络、权限、来源解析或 agent 标识错误时报告实际失败，不自动改换全局/项目范围，也不删除已有安装。若当前会话需要重新加载 Skill，说明安装与会话加载各自状态，并在可读取时先读取安装文件。

用户暂不安装或安装失败时，继续可独立完成的 AGENTS 和 docs 工作，明确 Notes 接入未完成；不能另造一套本地替代协议。用户仅要求设计或草稿时，描述该安装流程，不执行安装。

项目级可用目录可能是 `.agents/skills/`、`.claude/skills/` 或其他环境支持位置，以实际安装为准。仓库 Skill 目录应从普通文档检查中按范围排除，避免把外部模板当成项目当前参考。

## 与另外两个职责域连接

修改前从行动入口、模块名和机制名检索相关活动决定；按外部流程理解已有约束，不能把归档当作当前权威。当前参考在解释设计依据处链接唯一 Note，Note 链接当前参考和必要实现、验证入口。

已有源码入口提示是可用阅读路径，路径迁移时必须修复。只有项目惯例和具体误改风险支持时才增加提示，不为了检索机械铺设注释。

事实变化时交由外部流程同步相关记录；真实新决定与原决定的关系也按外部规范处理。迁移旧文中的理由时保留真实证据、独特后果与验证缺口，不从最终代码反向虚构当时讨论过的方案。

## 验收与缺口

能从实际任务找到相关决定；当前参考与理由分工明确；记录格式和工具只采用一套来源；外部依赖、版本及命令可追溯。Note 修改后的验证使用外部工具，分别报告结构、冻结与语义的实际覆盖范围。

工具不可用、已有格式未适配、历史依据不足或用户暂不授权相关操作时，记录具体未完成项，不生成替代实现、不称为已验证，也不阻止可独立交付的 AGENTS 和 docs 改动。
