# 项目结构总则

本规范用三部分保存工程上下文：**AGENTS 写常驻工程规则，docs 与模块参考写当前系统事实，Notes 写决策理由与取舍。**

## 总体结构

```text
项目/
├── AGENTS.md                  # 全仓常驻工程规则
├── README.md                  # 项目介绍与起步入口
├── docs/
│   ├── AGENTS.md              # 项目文档标准
│   ├── README.md              # 维护者文档导航
│   ├── doc-rules.json         # 文档检查配置与逐文件预算
│   └── ...                    # 架构、子系统、教程等，按主题组织
├── scripts/
│   └── check-docs.py           # 无已有等效工具时接入的检查脚本
├── <源码目录>/
│   ├── AGENTS.md              # 按需设置的局部工程规则
│   └── <模块>/README.md       # 模块使用、配置与限制
└── .agents/notes/             # 决策理由、替代方案与后果
```

这是职责与目标位置，不是空目录创建清单。源码沿用项目布局；子树指令按局部规则需要设置，模块参考按实际模块落位。docs 按真实内容增长；Notes 的创建条件和内部结构由外部 Skill 定义。

检查工具优先复用项目现有机制；图中的脚本与配置为默认接入位置，有既定约定时沿用。预算、本地入口与已有 CI 的要求见 [文档总则](docs/README.md#篇幅与自动检查)。

## 职责与连接

| 部分 | 正文职责 | 详细规范 |
|---|---|---|
| 根与子树 `AGENTS.md` | 直接写明全仓或局部常驻规则，补充必要阅读与命令入口 | [Agent 指令](agents.md) |
| `docs/` 与模块参考 | 描述当前行为、接口语义、使用方法和开发操作 | [文档总则及专项规范](docs/README.md) |
| `.agents/notes/` | 保留决定依据、真实替代方案、取舍与验证要求 | [Notes 接入](notes.md) |

**每项详细内容只有一个正文所有者。** AGENTS 写清要求并链接详情；参考需要解释设计依据时链接相关 Note；Note 链接当前参考和必要实现。规则摘要不代替完整参考，当前参考不重复决策经过。

项目 README 提供起步与后续入口，docs 导航按主题引导维护者。源码任务从根或适用子树指令找到相关规范、参考和决定；Notes 检索按外部协议执行。

## 采用与阅读

先读本总则，再读本次涉及的职责规范；处理 docs 时继续读取适用专项规范。子文件定义各自细节，不重复维护整套项目结构。

初始化、旧项目改造和后续更新分别执行 [初始化](../scenarios/initialize.md)、[迁移](../scenarios/migrate.md)、[维护](../scenarios/maintain.md)。迁移向标准位置收敛；存在外部稳定引用、工具约束或用户明确要求时，按文档总则记录有依据的例外。

外部 Notes Skill 的安装位置取决于用户选择的项目或全局范围及当前 agent，不等同于项目决策目录；安装与协议接入统一见 Notes 规范。
