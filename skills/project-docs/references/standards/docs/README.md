# docs 与模块参考总则

## 职责

文档说明当前系统，帮助读者理解、使用和修改。常驻工程规则见 [AGENTS 规范](../agents.md)，决策理由见 [Notes 接入](../notes.md)；整体位置见 [项目结构总则](../README.md)。

**每项事实只有一个正文所有者。** 上层解释自身及直接子层的职责和高层协作，再链接下层细节。源码或生成器已有权威定义时，正文解释语义，不手抄完整清单。

## 组织与导航

先确定读者、主题与允许展开的细节，再选择教程或参考。教程按前提顺序走向结果，参考按主题供查询；大量混合时拆分，少量附带内容明确标注。

页面先说明用途与范围，再展开细节。复杂内容提供页内导航；按读者需要从基本使用递进到高级用法和必要设计，避免开头堆满内部术语。

新文件用小写英文与连字符，保留 `README.md`、`AGENTS.md` 等工具约定名称。平级主题默认平铺，有独立读者、职责或任务群时再分组。日期和编号用于事件、决定及版本历史，不表示普通页面的完成状态。

每个当前维护页须能从项目入口经链接或有效生成导航找到。目录入口说明范围并链接直接主题，不复制子页面。项目 README 提供起步路径；docs 导航服务维护者，用户入口服务产品任务，已有有效 index 可复用。

## 写作与资源

**普通正文描述当前事实，设计理由链接 Note。** 不写开发流水账、实施进度、推理过程或逐行代码复述；事故与版本历史在各自范围保留必要时间信息。

说明影响使用的条件、默认值、失败与限制，按实际机制补充状态、资源、并发和兼容保证。依据实现核对命令与示例，不从旧文、相邻模块或惯例推断行为；示意与可运行内容明确区分。

沿用项目文档语言及明确格式约定；无其他约定时，一个自然段一条物理行。关键要求、限制和职责边界适量加粗，不整段加粗，也不另加 XML 强调层。

资源靠近所属主题，共享资源保留一个来源。生成内容注明输入、生成入口与新鲜度检查，先改来源再生成。网站复用正文，通过映射与导航发布，不维护第二份可编辑副本。

## 篇幅与自动检查

**采用时必须落实文件预算、检查工具和执行入口。** 为已存在的根与子树 AGENTS、架构等常驻文档按职责与阅读成本确定上限，并留出合理余量；不直接以当前长度定预算，不照搬 DSH 数值。完整参考按需要设置，不统一压成摘要。

**超限先调整内容归属，再精简重复；必要内容确需空间时，说明理由调整预算。** 不删除关键保证，也不通过排除受影响正文或自动抬高上限消除报错。

已有等效检查优先复用；没有则接入本 Skill 提供的脚本。脚本、预算配置及本地入口须纳入项目版本管理，已有 CI 同时调用该入口并保留失败状态；没有 CI 时提供本地命令。提交前钩子只作辅助，接入与升级见 [文档检查器](../../tools/check-docs.md)。

## 同步与核对

**实现变化时同次更新受影响正文、示例和资源。** 移动或删除文件须修复全部引用及消费者，包括源码、配置、脚本、测试输入和网站映射。旧项目向标准位置收敛；确有外部稳定引用、工具约束或用户要求的例外写明依据，具体处置见 [迁移场景](../../scenarios/migrate.md)。

核对事实与实现、类型与语义、导航与归属是否一致。操作在授权和环境允许时原样执行，检查实际结果；不能执行时说明前提与未验证项。区分静态检查、运行验证与人工判断，不把跳过或未覆盖当通过。

项目已有检查优先复用；自带脚本的配置与检查边界见 [文档检查器](../../tools/check-docs.md)。Notes 专用检查交由外部 Skill，采用记录与交付按对应场景处理。
