# 事故复盘

## 职责与创建条件

`docs/postmortem/` 记录已经发生的失败，解释**事故机制、为何漏检及防复发措施**。适合记录机制隐蔽、暴露系统性验证缺口且重查代价高的事故；普通修改或显然错误不自动生成复盘。

## 内容与组织

一篇一个事件。开头用短摘要说明影响、根因、漏检原因与关键改进，再展开：

- 影响范围与有证据的时间线。
- 触发条件、根因与促成因素。
- 测试、工具或规范为何没有阻止事故。
- 修复、防复发措施、验证证据与未决项。

区分事实、推测和未知；不能从最终代码倒推事故经过。措施给出可观察完成条件，未执行项保持未完成。仅使用项目实际责任机制，不编造人员或审批。

文件按项目统一的日期或稳定编号命名，并带事件主题。多个事件通过 README 导航，不复制时间线。当前保证更新所属参考，长期规则更新 AGENTS 或详细规范，设计取舍按外部 Notes Skill 处理；复盘链接这些结果。

## 同步

新证据、因果纠正或行动完成时更新，保留事件时间语义；复盘不成为当前接口、规则或任务的第二份正文。
