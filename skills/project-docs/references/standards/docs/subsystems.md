# 子系统参考

## 职责

`docs/subsystems/` 按子系统定义**类型、接口语义和调用方与实现方共同依赖的保证**。页面归属依据类型声明或机制职责确定，不按每个 API、实现类或调用方重复建页。

## 内容与组织

开头说明子系统范围、参与方及权威实现，再按概念或接口组织查询内容。主要说明：

- 类型与字段的含义、单位、默认值、必填条件及非法输入结果。
- 操作前提、状态转换、成功提交点和失败后的状态。
- 适用的并发、顺序、取消、资源取得与释放要求。
- 适用的协议、持久化、兼容、恢复和未知结果处理。

只写实际存在的机制。整体执行流程链接架构，模块专有用法链接模块 README，决定理由链接 Note；局部顺序仅在解释接口语义需要时展开。

类型定义和 API 可由源码生成，或使用有防漂移检查的引用片段；已有生成内容不再手抄。生成区域可完整列出所属接口，手写正文解释含义和使用后果。

默认一子系统一页、逻辑平级页面平铺；多个主题通过 README 导航。只有存在独立子主题时才分组，不按文件数量拆分。

## 同步

文档化类型、操作语义、状态或兼容保证变化时同次更新所属页面，核对相关消费者仍能依此理解并实现相容行为。
