# 项目开发与评审规范

## 职责

`docs/standards/` 保存**需要展开说明的已采纳工程要求**。AGENTS 直接写明必须常驻的规则并链接本处；这里解释适用条件、判断方法和示例，不重复维护另一份常驻规则清单。

要求来自用户指令、有效团队约定或已采纳决定。模板、个人偏好和外部最佳实践不能自动成为项目政策；实现与要求不符时说明差异，不悄悄放宽。

## 内容与组织

本规范将详细开发要求与领域防错统一放在 `docs/standards/`。按独立主题命名，如 `coding.md`、`dependencies.md`；防错规则归 `docs/standards/defensive-patterns/`，按修改对象或领域分组。

每条要求明确适用对象、强制或建议性质、具体义务、违反判据和必要例外。附真实检查入口或人工判断方法；需要消除歧义时提供正反例。

防错页还须说明阻止的错误类别和必须维持的性质。事故证据链接复盘，决定依据链接 Note；规则本身应能独立理解。异常处理沿用项目既有责任机制，不新增审批角色。

README 按开发与评审对象导航，根或适用子树指令引导读取。紧密相关的规则放一起，有独立职责时再拆分。简短规则已由 AGENTS 完整表达且无需展开时，不再创建对应空页。

接口语义归子系统或模块参考，环境操作归 development，测试策略归 testing。既有规范树的收敛与例外处理遵循迁移场景，不建立两套竞争正文。

## 同步

要求新增、变化或退役时同步详细规范、AGENTS 中的适用摘要、导航与实际验证方式。
