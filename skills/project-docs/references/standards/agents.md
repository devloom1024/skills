# 根与子树 AGENTS.md

## 职责

`AGENTS.md` 保存 agent 开发和评审时必须遵循的**常驻工程规则**。

- 根文件：全仓适用、每次会话都需要知道的规则；辅以简短项目定位、目录图谱、常用命令和必读入口。
- 子树文件：该范围内的专用规则，明确适用对象，不重复根规则。按需要创建，不逐目录铺设。
- `docs/AGENTS.md`：项目文档标准，规定内容归属、组织、写作、同步与检查；具体内容见 [docs 规范](docs/README.md)。

## 选择内容

从用户要求、有效项目约定、当前实现和活动决定中提取已确认的规则。优先保留影响架构、兼容性、安全、生命周期、代码约定、测试和文档同步的要求；不因目录结构或个人偏好推导项目政策。

**全仓规则放根文件，领域规则放适用子树。** 子树直接写清必要约束，不能只留下阅读链接。详细机制与接口放 docs 或模块参考，理由与被否决方案放 Notes，操作流程放 Cookbook 或专项 Skill。

实现进度、单次计划、迁移清单、评估报告和对话过程不进入常驻规则。采用基线与遗留事项按场景记录，不扩写为每次会话的必读正文。

## 写法

**每条规则独立可理解**：写明对象、必须采取或禁止的行为、必要条件和例外，再链接详细规范或理由。通常一至三行；长度服从准确性，不靠删掉关键条件压缩。

例如，项目已采纳请求安全规则时，写「携带凭据的请求必须拒绝重定向，并验证目标未被访问」，再链接安全规范。只写「修改请求前阅读安全规范」不足以表达这条约束。示例不是所有项目的默认政策。

规则摘要与详情各有职责，不复制详情正文。避免「保证质量」「遵循最佳实践」等无法指导修改的口号，也不展开故事、完整示例或操作教程。

关键义务、职责边界与禁止项使用少量加粗，不整段加粗或反复强调；无需额外 XML 标记。

## 阅读与命令

将必读入口写成明确条件，例如「修改 packages 前读架构」「修改文档遵循 docs/AGENTS.md」。链接项目真实路径，避免笼统要求通读全部文档。相关决定的检索与维护遵守 [Notes 接入](notes.md)。

常用命令取自实际配置，注明必要工作目录、前提和用途。长操作步骤链接开发或测试文档；不复制完整脚本清单，不把列出命令当作已经运行。

## 维护

先读生效指令与兼容入口，保留有效用户要求；存在符号链接时编辑真实文件，避免多份正文。确认当前 agent 的加载方式，不假定它会自动读取全部子树。

工程约束变化时同步对应规则及详情链接。篇幅过长先迁出错位内容、合并重复表达；保留必要规则，不把子树改成纯导航。检查每条规则是否具体、适用范围是否清楚，以及新会话能否在修改前读到它。
