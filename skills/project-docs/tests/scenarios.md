# 行为验收场景

在独立临时或缓存项目运行，不让评估者看到预期答案。测试请求只描述用户任务；本文件的验收条件由主 agent 在产物完成后核对。

| 场景 | 请求 | 可观察条件 |
|---|---|---|
| 已有任务执行器 | 按 Skill 整理现有文档，使后续 agent 能准确开发 | 原 jmvn/语言/Git 约束保留；同步/异常/旧字段语义准确；Redis 保持未实施；有独立文档标准；不产生空壳 |
| 空项目 | 建立 agent 开发文档入口 | 最小指令和文档标准；不虚构命令、架构、实现或事故 |
| 既有 ADR | 补文档组织，保留原引用 | 原编号、路径、内容保留；显式说明决策角色与映射；external 状态需人工核对 |
| 提案已实施 | 根据 cache.py 更新决定记录 | 原提案日期不变；进入 implemented；规范头部、当前决定、真实替代方案和后果；无提案期计划；不声称缺失调用方已完成集成 |
| 教训晋升 | 三个独立日期的配置读取失败教训形成长期规范 | 领域要求进入所属防错文档；根入口只导航；LESSONS 仅简述、证据和去向；不编造实现已核验 |

附加压力场景：用户明确只改模块一个配置字段，不能触发全仓迁移；再次运行初始化，复用现有所有者而非创建重复文件；用户不提供源码，必须报告证据缺口。

## 目录内部组织扩展场景

请求：整理一个仅有确认文档、没有源码的项目；其 system.md 混合两个独立契约，guide.md 记录一个具体操作并引用根 images 下的资源；已有 user/index 是稳定网站入口，ADR 编号被外部引用。

验收：明确每类目录文件单位、命名、平铺/分组、入口和资源约定并写回目标文档；子系统拆分有依据，或解释保留同页的契约关联；教程名能表达任务；导航不复制正文，既有 user/index 复用、不创建竞争入口；资源移动前检查消费者并修复相对链接；原 ADR 路径与正文保留；不声称未提供的实现已验证；不引入空目录或重复决策清单。

执行第二轮维护后核对所有者和导航是否重复、是否有无依据重命名。机械检查与人工导航核查分别报告；文件存在不等于页面可发现。

## 决策专项协作与教程编写

仅project-docs：建立项目自己的决策格式/生命周期约定，保留ADR编号与accepted含义；对单条提案核对源码范围并基本维护，不因缺少专项Skill停止；不把无工具的归档标成已验证冻结。

教程：从真实生成器编写贡献者教程，在临时输出目录原样运行，核对输出内容而非仅退出码；说明清理、副作用和失败条件；不改业务源码、不写真实用户配置，命令变化复用唯一教程。

协作：project-docs先写回项目规范，decision-records再依同一份约定治理；两者不覆盖彼此采用的项目状态、编号或格式，未集成的脚本不能写成项目内已有命令。部分取代不丢旧保证，提案验收未完成不改implemented。

## 项目开发规范

| 场景 | 请求与资料 | 可观察条件 |
|---|---|---|
| 新项目已有真实开发约定 | 有本地工具源码和已采纳的命名、编码规则，请求整理为后续开发与评审可用的文档 | 默认使用 docs/standards；按实际主题组织，入口区分强制与建议、按任务导航；每条规则有范围、判断依据、适用示例、验证和真实例外；旧资料改导航，不维护双份正文 |
| 已有稳定规范路径 | 已用 conventions/index、领域防错页，要求保留路径 | 显式映射为正式规范及领域防错角色，不强制迁到 standards 或生成竞争入口；根 AGENTS 导航到现有规则，docs/AGENTS 仍负责文档写作 |
| 无工程规则的最小项目 | 没有已采纳的编码或评审要求 | 不生成空 standards 树，不凭模板创造标准、事故、工具或审批职责 |
| 单条正式规则维护 | 只更新一个领域要求或将真实 LESSONS 晋升 | 完整正文只有一个所有者，根行动入口/规范导航/LESSONS 去向同步；已有 testing 和 development 的内容引用而非复制 |

模板应用时，在独立样本核对生成物的任务导航、规则等级、具体违反判断和保留例外，不以标题齐全替代规范可执行性。
