# 执行、证据和阶段结果

与 [YAML 格式](workflow-format.md) 配合使用。Agent 维护本次会话中的执行状态，不要求实现状态数据库或在项目中落盘。每次调用 Skill 前先读取实际 SKILL.md 及其按任务所需资源，不能只凭名称或先前记忆执行。

## 起点与交接

开始记录本次请求、授权范围、流程文件内容和顺序、项目规则，以及相关文件/版本的实际起点。已有 Git 改动、未跟踪文件、用户修改和其他进程写入均需区分；Git status 不是本轮归属证明。可对相关文件做内存或隔离快照/字节摘要，不为了保护起点 reset、stash 或切分用户提交。

Git 查询采用目标环境支持的只读方式，例如 `git --no-optional-locks -c diff.autoRefreshIndex=false ...`；diff 加 `--no-ext-diff --no-textconv`，避免外部 diff 与文本转换。不要把派生缓存和测试临时产物算成业务修改。无 Git 时仍可按文件起点与实际操作核对，不要求初始化仓库。

传递给下一个 Skill 的内容包括同一个任务/授权、已发生的操作、实际产物与版本、保留义务、发现及解决证据、未验证事项。无需为每次交接新建 Markdown。多个 Skill 在同一上下文中依次应用即可，不默认派生子 Agent；环境与用户明确支持委派时，仍需保护顺序、结果和共享状态。

## 阶段结果

每个 Skill 完成后保留简短证据；step 结束后统一汇总：

```yaml
step: simplify
status: completed
changed: true
has_findings: false
has_unresolved: false
```

这是运行报告示意，不是流程 YAML 中的配置字段。

| 字段 | 定义与依据 |
|---|---|
| status | completed：本阶段任务已执行并得到结论，不表示没有问题；skipped：when 确定为假，Skill 未调用；blocked：缺条件/证据/授权或无法判断 when，不能继续；failed：实际执行失败且本阶段要求未完成 |
| changed | 阶段结束相对阶段起点，授权范围内仍存在归属于本阶段的文件差异。包括新增/删除/修改；原有改动不算，修改后完全恢复不算净变更，但要报告操作。不能确定归属时为 null |
| has_findings | 本阶段至少一个 Skill 发现具体需要处理的问题（缺陷、正式规范不符合或明确缺失交付条件）。纯偏好或普通简化候选不自动算问题。发现后修复仍保留 true；检查范围内未发现为 false，证据不足为 null |
| has_unresolved | 本阶段交接时与本阶段任务及继承问题有关的待解决项。全部有解决/有依据排除证据时 false；已知剩余为 true；不能确认时 null。未验证与已证明失败区分，但必需证据缺失不能被记为全部解决 |

布尔字段只取 true/false/null，未知用 null。阶段完成的「检查任务」可以留下未知项；若未知意味着本阶段要求的动作本身无法完成，则 blocked。检测到问题是评审的正常结果，不应仅因存在发现就自动 failed。

多 Skill 汇总：status 只有全部要求已完成才 completed；前面 failed/blocked 时立即保留该状态，剩余 Skill 不调用。changed 对比整个 step 起点；has_findings 有一项确认发现即 true，否则有未知则 null，其余 false。has_unresolved 按继承与新增问题逐项核对，后项确有解决证据可消项，不能简单用最后一个 Skill 的 false 覆盖先前问题。前面非阻塞的未知应继续保留，除非后项确实补齐了证据。

条件跳过的 step：status=skipped、changed=false，两个问题字段为 null，因为该步未检查。未到达的 step 只在报告标注「未执行」，不伪造 completed 或 skipped，也不为它生成可用结果。

## 条件、停止与收尾

1. 先完成完整配置与 Skill 可用性检查，再执行首步；连潜在跳过分支中缺失的 Skill 也需报告，避免后半程才发现配置不可执行。无需提前加载所有 Skill 的详细参考。
2. 到达 step 时根据已结算的前步结果判断 when，并写明条件值及证据；假时跳过并继续，未知时 blocked 停止。三值 all/any 语义见格式契约。
3. 任一 Skill failed/blocked 时停止剩余工作，报告失败位置、已完成部分和实际残留改动。不自动回滚、补造外部证明、调用后续「收尾」或把失败改成 skipped。允许局部诊断后如实确定状态，不无限重试。
4. 在当前授权范围内，修复/验证可作为某个明确任务的一部分。只读评审本身不授权修复；流程 instruction 不能覆盖用户只读约束。只读发现仍可 completed，changed=false，由 YAML 条件决定是否走到后续阶段。
5. 结束报告所有已执行阶段结果、Skill 顺序、跳过及未到达、改动/命令/版本证据和未解决项。全部步骤已遍历也不等于验证无缺口；存在 has_unresolved=true/null 时明确限制，不能宣称质量全部通过。

后续改动使先前评审/验证证据失效时，不能沿用旧结果证明最终产物；在当前授权内复核实际受影响部分并报告新的证据。没有条件复核时明确最终状态尚未验证，不通过隐式回边反复执行流程。恢复中断运行同样先核对外部状态，不能重放提交、发布或其他有副作用动作。

质量维护通常是简化 → 评审 → 文档同步。每个专项 Skill 原有的保留能力、同快照证据、项目规范和文档约束继续生效，不为凑满流程强行删除代码、创建经验或决策。只有真实返工、漏检等事件才提炼相应经验，普通潜在风险不能改写成既有事故。
